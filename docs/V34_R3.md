# V34 R3: one framework, separate task checkpoints

The native V34 CNN + GRU(16,24) + MLP controller is shared by AR, OD and OT: nine conditions, thirteen ordered actions, three risk slots and one rate output per action. Checkpoints and evaluations are separate. AR uses the pinned R1 four-QP checkpoint/config/calibration bytes through the native evaluator. AR is never retrained or refitted by R3. The R2 joint pipeline remains the comparison and is unchanged.

OD learns normalized FN, FP and localization increments from official COCOeval inference matching. OT learns increments of `1-HOTA`, `1-DetA`, `1-AssA` after official MOT preprocessing on causal contexts. These are training surrogates; final quality is cohort COCO mAP or full evaluated sequence TrackEval metrics. Source consistency has distinct fields and is not a GT accuracy guarantee.

All training targets come from thirteen actual encoded/decoded packets with x264/x265 and QP `{30,35,40,45}`. There is no gradient through codec or frozen task models. TRAIN fits weights/scales/fixed proposals; CAL fits empirical grouped residual bounds without changing weights. OT uses identity data for warm training, then one frozen seed-303401 source-only rollout policy; final seeds share the measured rollout data. Seeds measure optimization variation, not independent data experiments.

At deployment CNN, TRAIN-fixed and seeded random proposals each use identity plus three distinct real probes. Component risk bounds and measured source constraints gate candidates; minimum paid bytes wins, with action index breaking ties. Missing/mismatched/nonfinite calibration falls back to identity. Probe state is transactional and only the winner commits. Receiver tracking runs independently on selected pixels.

DEV considers the predeclared equal-valued component grids (OD `0,.01,.025,.05`; OT `0,.005,.01,.025`), with and without the risk gate. It locks one policy across both codecs and all seeds. TEST can shard by codec but must consume that exact DEV policy/checkpoint binding. Raw QP points remain available; nonmonotone, duplicate, flat or insufficient-overlap curves cannot support accepted BD-rate. Cubic overshoot/negative derivative or a cubic–PCHIP difference exceeding five percentage points marks interpolation sensitivity. This threshold is an engineering diagnostic.

The historical default has one OT CAL sequence, so it cannot confirm or promote an improvement. Context windows and codec/QP conditions do not increase independent sequence count. Additional cohorts can be supplied by a content-pinned manifest; MOT17 camera detector variants collapse to one camera identity. Audited unused TEST IDs, pixels and groups are required for confirmation. The Kaggle downloader is pinned to MOT20; other benchmarks require explicit local data mounts.

## Local stages

Use `python -m adaptive_vcm.v34r3.runner --experiment od|ot --stage STAGE --origin source-origin.json --out OUTPUT` with data mount arguments, and `--parent PARENT` for dependent stages. The packaged origin includes exact R3 source hashes and the frozen c445ef3c baseline manifest. OT requires the pinned TrackEval checkout. AR accepts only `--stage evaluate --parent native_manifest.json`.

OD: `measure-identity → train-final → evaluate DEV → evaluate TEST`.

OT: `measure-identity → train-warm → measure-rollout → train-final → evaluate DEV → evaluate TEST`.

Partial measurement caches contain only completed thirteen-action condition rows. Restart validates source/annotation/map/model/codec/prefix lineage and replays committed streams before reuse. Completed stage files are content-checked. WARM checkpoints cannot enter final evaluation. A timeout recovery must make row progress before another automatic continuation is accepted; other errors require inspection.

## Private Kaggle execution

`python -m scripts.v34r3_kaggle` prepares and validates source-only notebooks; it does not submit. Dataset inputs have explicit versions (COCO version 2; native AR reference data version 1); MOT20 Hugging Face revision, TrackEval commit and supervision 0.27.0 are pinned. Run environments, actual source pixels, annotations, packets and outputs carry hashes.

`python -m scripts.v34r3_workflow --pool PATH_TO_EXISTING_POOL --out NEW_R3_ROOT --run` dispatches only authorized accounts with verified quota/available slots. It never cancels or restarts R2 jobs. Submission intent is persisted before push; ambiguous pushes/uploads are reconciled instead of blindly repeated. Parent state is uploaded privately as a hash-checked `state.zip` so nested official metric files survive dataset transport. Credentials, weights, datasets and mutable outputs are excluded from Git.

Authorized accounts are `thuha1205`, `qktttttttttt`, `huolgggnuyen`, `baoancut`, `trmnguyn111`. The dedicated workflow root owns `plan.json`, `state.json`, payloads, private state uploads, downloaded artifacts and receipts. Worktree HEAD and config bytes are locked for the workflow lifetime.

Reports include raw points, actual bytes including headers, all deployed probe work, source/risk audits, calibration group counts, component violations, risk errors, shortlist entropy/frequencies and checkpoint/policy hashes. Identical-pixel frozen detector inference is memoized across experimental arms using separate sender/receiver caches. Representative uncached inference work and actual cached guard time are labelled separately; they are not wall-clock timing claims.

## Evidence status

Before release, the real-codec R3 fixture suite passed 41 tests, including full OD QP/codec coverage, all three checkpoint seeds, two-window OT rollout/replay with official metrics, heldout-label sentinels and native AR action/packet/decoded prediction parity. The initial payload/workflow plus R2 regression suite passed 24 tests. These fixtures establish implementation behavior, not real-data rate/quality improvements. Final verification and review receipts are recorded in the release review document.
