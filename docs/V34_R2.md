# V34 R2: preprocessing for OD, OT and a shared AR+OD+OT packet

R2 is an opt-in implementation of the [literature-informed design](V34_R2_METHOD.md). It is a testable research recipe, with no measured improvement claim. `adaptive_vcm/v34`, its configurations and its checkpoint loader are unchanged. The existing AR R1 QP4 checkpoint/results remain the AR baseline.

## What runs

`adaptive_vcm.v34r2.runner` supports `od`, `ot`, and `ar_od_ot`.

| Mode/source | Protected regions | Active source constraints | Available GT target |
|---|---|---|---|
| OD / COCO image | Object boxes, soft context with a minimum halo for small objects | OD | Frozen detector loss |
| OT / MOT video | Associated ByteTrack detections, including matched low scores; bounded decaying track-coordinate history | OT | Official HOTA on a finite positive-pedestrian context |
| Joint / K400 video | Union of the original AR maps, OD context and OT track maps | AR + OD + OT | AR CE |
| Joint / MOT video | Same union | AR + OD + OT | OT context HOTA |
| Joint / COCO image | OD support | OD | OD detector loss |

A COCO still image is not repeated to manufacture AR/OT supervision. The K400 and MOT sources have no simultaneous three-task GT. The joint model learns masked GT risk and source risk separately; joint source constraints cannot establish joint GT accuracy.

All modes retain the original 13 six-coefficient spatial filters, x264/x265, QPs **30, 35, 40, 45**, medium preset, seeds **303401/303402/303403**, and 16-frame video windows. OD stays GOP 1; videos stay closed GOP 16 with no B frames. No geometric warp, side-channel mask, codec gradient or old-controller reuse is introduced.

## Targets, state and selection

Every action is actually filtered, encoded, decoded and scored. Actual paid packet bytes determine rate. The cache records independent `gt_damage`, `source_damage`, their masks, packet hashes and the common tracker prefix hash. Damage is an increment from the encoded identity anchor. OD source damage uses two-way matching with missing objects, extra detections, class mismatch, IoU and confidence changes. AR keeps the source KL/feature constraint and uses CE as its separate GT target.

The OT source tracker is continuous. Every candidate clones the same receiver prefix. A candidate never changes a competing candidate; only the selected branch commits. State is independent for every split, source sequence, codec, QP and evaluation arm/seed. Maps use source tracks only, with no future-window or GT access.

Offline TRAIN/CAL candidates share a locked **identity** prefix. Runtime arms use their own **selected** prefixes. This is a controlled offline/online state mismatch, explicitly recorded in the cache; it is not on-policy training. Context length is a locked configurable 64 previous frames plus the current window. The context HOTA target invokes pinned TrackEval HOTA directly on positive pedestrian boxes. It omits MOT distractor preprocessing and is not an exact decomposition of full-sequence HOTA. Final OT reporting uses TrackEval's MOT dataset preprocessing and full continuous streams.

The new controller predicts measured rate, three GT risks, three source risks, source feasibility and action ranking. Risk scales come from TRAIN only. Feasible actions receive soft ranking targets based on measured rate. CAL never updates model weights; residuals are aggregated by image/clip, or by MOT sequence, before the empirical upper statistic. The one CAL MOT sequence does not justify a coverage guarantee.

Deployment evaluates **identity + three nonidentity candidates**. CNN, TRAIN-fixed and seeded-random shortlists have the same probe count. The source guard checks all active tasks and the actual byte budget, then chooses the feasible packet with the fewest bytes. Identity is always the fallback. Predicted risk/feasibility are ranking/diagnostic signals; measured source costs enforce the constraints.

Each active task consumes the same decoded selected packet. Receiver tracking runs continuously and independently. Sender timing includes source support, controller work, and every candidate's preprocessing, encode, decode, inverse and guard work. Extra DEV diagnostics are excluded from deployment work and saved separately.

## Experimental controls

The default recipe is `configs/v34_r2_qp4.json`. OD/K400 counts are TRAIN 192, CAL 64, DEV 64, TEST 64. MOT sequences are disjoint: TRAIN 02, CAL 05, DEV 03, TEST 01, initially 256 frames per sequence. These are historical exploratory cohorts. MOT20-05 has appeared in earlier evaluations; moving it to CAL does not create an untouched confirmation dataset. An independent dataset/sequence manifest must be locked before confirmatory claims.

The `--ablation` argument selects a common R2 training/measurement harness:

| Ablation | Support maps | Target/guard family |
|---|---|---|
| `baseline` | Legacy | Legacy one-way OD / per-window OT |
| `map_only` | R2 | Legacy |
| `target_only` | Legacy | R2 |
| `combined` | R2 | R2 |

The legacy ablation uses the new controller/training and transactional state harness; it is not an exact replay of an R1 checkpoint. Use the frozen R1 artifact separately for that comparison. All R2 ablations use identical source counts, seeds, codecs and QPs. CNN/fixed/random selector controls are produced by every run. Full-bank source and available-GT upper bounds are DEV-only diagnostics; they never select TEST packets.

Reports retain all raw same-QP points, actual bytes/bpp, COCO mAP/AP50/AP75 and small/medium/large AP, and OT HOTA/DetA/AssA/IDF1/MOTA/FP/FN/IDs. Undefined COCO size bins are `null`. BD values are suppressed for flat, nonmonotone or insufficient-overlap curves. PCHIP remains a sensitivity check. OD uncertainty is a paired image bootstrap; the one OT held-out sequence has no sequence CI. Three optimization seeds are not three independent datasets.

Each OD bootstrap draw must satisfy the same BD validity rules as the primary
curve. Reports include requested/valid draw counts and the valid fraction;
intervals are conditional on valid draws and remain null when none are valid.
Invalid curves cannot pass the BD acceptance flags. Local runs verify origin
file hashes against the executing source before measurement, and evaluation
rejects checkpoints with different settings, experiment or frozen task heads.

## Running

From this repository, with the usual PyTorch/torchvision/COCO dependencies, FFmpeg with x264/x265, `supervision==0.27.0`, `defusedxml`, and `tabulate` installed:

```powershell
python -m adaptive_vcm.v34r2.runner --experiment od `
  --od-root <COCO-root> --annotations <instances-json> `
  --origin <source-origin.json> --out <new-output-directory>
```

OT additionally requires `--mot-root` and `--trackeval` pointing to the pinned TrackEval Git checkout at `12c8791b303e0a0b50f753af204249e622d0281a`. Joint mode requires all roots, including `--ar-root`. Select `--ablation map_only`, `target_only`, `baseline`, or `combined` before training. Output directories are immutable; every run creates fresh targets, checkpoints, calibration and held-out streams.

For a reproducible Kaggle notebook, commit the source and run:

```powershell
python -m scripts.v34r2_kaggle --experiment ot --account <account> `
  --ablation combined --out <new-payload-directory>
```

Preparation verifies the source bundle and compiles the notebook; it does not submit a job. The notebook mounts the proper datasets, downloads all four pinned MOT sequences when needed, installs the pinned tracker, measures targets, trains three fresh controllers and evaluates. Full real-data runs are substantially more expensive than local fixture tests. No accuracy or BD-rate gain follows from successful smoke tests.

## Reproduction limits

- Context/margin/history/temperature values are engineering hypotheses to select on TRAIN/CAL/DEV, not constants established by the cited papers.
- The 0.5 pp acceptance limit, if used, must be locked as an internal requirement before independent confirmation.
- Full old-versus-new R1 OT comparisons still need the same dataset, frames, checkpoint, codec and metric protocol. Differences between earlier unmatched runs cannot identify the effect of dropping QP 50.
- R2 supplies executable ablations and local integration evidence. New real-data mAP/HOTA and confidence intervals must be obtained from those runs.
