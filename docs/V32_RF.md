# V32-RF and Video Swin receiver experiments

The paired experiment starts from the exact verified V32-VC plain LAST CNN. It preserves FIT48 and refits scalar proxy calibration on CAL12; PROXYVAL4 diagnoses mismatch without weight updates. Two identical starts train for two epochs each. The proxy arm uses the fixed virtual codec in forward. The real arm uses actual received x264/x265 decoded uint8 RGB in forward, with the virtual codec Jacobian in backward. This is a surrogate derivative, not an exact H.264/H.265 gradient. Both optimize frozen task loss +0.01 estimated paid bpp +10 RGB MSE +0.1 frozen feature cosine loss.

Primary settings: medium, AR GOP16/OD GOP1, bframes0, scenecut off, closed GOP, 25fps, QP30/35/40/45/50. Independent packet decoding and received-grid inverse remain unchanged. DEV32/TEST32 include historical V30-B, guarded warm/proxy/real CNN and retarget arms, and forced plain CNN diagnostics. Fast TEST8 tests preset transfer without incompatible V30-B. Paid bytes count the elementary stream, fixed header and ROI grids against source T*H*W.

AR additionally scores a frozen torchvision Video Swin-T K400 evaluator. It uses the official spatial transform on the same 16 received frames; this does not reproduce the published multi-clip 32-frame benchmark. Each backbone's results are reported separately. A stronger task classifier alone is not evidence of better preprocessing.

The separate AR receiver experiment repeats the fixed paired RF fit, then freezes the RF-real CNN and trains only a Conv3D RGB head on pretrained, frozen Video Swin features. The head begins at zero residual, upsamples features to original geometry and limits changes to0.1 RGB. It trains on real decoded FIT48 streams, two epochs, task +10 MSE +0.1 feature loss, LAST. Rate is constant after decoding. DEV32/TEST32 compare anchor and forced RF-real streams with/without restoration; paired variants retain exactly the same bitstream and paid bpp. Restoration weights are preinstalled, excluded from per-video bytes and reported separately with inference time. This variant explicitly adds a learned receiver operation after the standard decoder.

All jobs are public by the user's authorization. Source and warm runtimes are immutable ZIPs; original checkpoint loaders run unmodified under a separate import alias. Outputs include TRAIN/calibration/proxy diagnostics, checkpoints, packet hashes and receiver evidence, evaluator/environment hashes, and complete/failed status in an archive. Submission is not a performance result. No gain or BD-rate target is claimed before the returned evidence is checked.

Three payloads use `python -m scripts.v32rf_kaggle --task ar|od --mode rf|post` with explicit original V30/warm checkpoint and runtime paths. Post mode requires AR. Training CLIs are `adaptive_vcm.v32rf.train` and `adaptive_vcm.v32rf.post_train`; evaluation CLIs are `adaptive_vcm.v32rf.evaluate` and `adaptive_vcm.v32rf.post_evaluate`.
